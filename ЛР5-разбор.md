# ЛР5 — код и показ работы

Ветка `25`. Короткевич А.Г., группа 320602, вариант 13.

## Что требовалось

Взять React-приложение из ЛР4 и подключить к собственному API из ЛР1–ЛР3.
Загрузить список через GET, реализовать POST/PUT/DELETE, показать загрузку,
ошибки и повтор запроса. Изменения отображать оптимистично, при ошибке откатывать.
Использовать JWT. Дополнительное улучшение — отмена загрузки через AbortController.

| Работа | Ветка | Данные | Запуск |
|---|---|---|---|
| ЛР4 | 24 | localStorage, автономная коллекция | Только клиент |
| ЛР5 | 25 | PostgreSQL через Express API | Сервер и клиент |

Публикации ЛР4 не удаляются. В ЛР5 localStorage хранит JWT, а не коллекцию.
База использует существующие таблицы Posts и Users, новой миграции нет.

## 1 Сначала сделали сервис API — client/src/api.js

URL берётся из VITE_API_URL или используется localhost:3001. Это адрес API,
а не адрес страницы. Страница открывается на localhost:5173.
Функции readToken/saveToken/clearToken работают с ключом game-media-jwt.

```jsx
 16 | async function request(path, { method = 'GET', body, signal, auth = true } = {}) {
 17 |   const headers = { Accept: 'application/json' };
 18 |   if (body !== undefined) headers['Content-Type'] = 'application/json';
 19 |   const token = auth ? readToken() : '';
 20 |   if (token) headers.Authorization = `Bearer ${token}`;
 21 |   let response;
 22 |   try {
 23 |     response = await fetch(`${API_URL}${path}`, {
 24 |       method, headers, signal, cache: 'no-store',
 25 |       body: body === undefined ? undefined : JSON.stringify(body),
 26 |     });
 27 |   } catch (error) {
 28 |     if (error.name === 'AbortError') throw error;
 29 |     throw new Error('Сервер недоступен. Проверьте, запущен ли API, и повторите запрос.');
 30 |   }
```

Функция request — общее место для HTTP-запросов. method задаёт метод,
headers — заголовки, body — содержимое запроса, signal — возможность отмены.
JWT автоматически попадает в Authorization. JSON.stringify превращает данные
формы в строку. await ожидает ответ, не блокируя всю страницу.

При сетевом отказе fetch бросает исключение. При HTTP 500 запрос сам по себе
может завершиться нормально, поэтому дальше проверяется response.ok.
response.json читает JSON. Для DELETE 204 тело не разбирается, поскольку его нет.
Ошибка получает status, чтобы отличить истёкший сеанс 401 от другого отказа.

```jsx
 46 | export const fetchPosts = signal => request('/posts', { signal });
 47 | export const addPost = body => request('/posts', { method: 'POST', body });
 48 | export const updatePost = (id, body) => request(`/posts/${id}`, { method: 'PUT', body });
 49 | export const deletePost = id => request(`/posts/${id}`, { method: 'DELETE' });
 50 | export const login = body => request('/auth/login', { method: 'POST', body, auth: false });
 51 | export const register = body => request('/auth/register', { method: 'POST', body, auth: false });
```

Это конкретные операции. Компонент вызывает addPost(values), а сервис знает,
что нужно отправить POST /posts. Axios не устанавливался: по заданию разрешён fetch.

## 2 Добавили вход — client/src/components/AuthForm.jsx

```jsx
 11 |   async function submit(event) {
 12 |     event.preventDefault();
 13 |     if (busy) return;
 14 |     if (!email.trim() || !password.trim()) { setError('Заполните email и пароль.'); return; }
 15 |     setBusy(true);
 16 |     setError('');
 17 |     try {
 18 |       const credentials = { email: email.trim(), password };
 19 |       if (mode === 'register') await register(credentials);
 20 |       const { token } = await login(credentials);
 21 |       try { saveToken(token); } catch { throw new Error('Браузер запретил сохранение входа. Разрешите localStorage для этого сайта.'); }
 22 |       setPassword('');
 23 |       onAuthenticated(token);
 24 |     } catch (cause) {
 25 |       setError(cause.message);
 26 |     } finally {
 27 |       setBusy(false);
 28 |     }
```

submit отменяет обычную отправку формы и проверяет поля. При регистрации
сначала вызывается register, затем login. Из ответа входа берётся token,
сохраняется в localStorage, после чего App переключается на коллекцию.
busy блокирует повторную отправку, catch показывает ошибку, finally снимает блокировку.
Пароль не сохраняется в localStorage и очищается после успешного входа.

## 3 Связали сеанс со страницей — client/src/App.jsx

```jsx
  6 | export default function App() {
  7 |   const [token, setToken] = useState(readToken);
  8 |   const [notice, setNotice] = useState('');
  9 |   function logout(message = '') {
 10 |     clearToken();
 11 |     setToken('');
 12 |     setNotice(message);
```

readToken используется как функция-инициализатор useState. При обновлении

## 4 Заменили локальную загрузку серверной — PostList.jsx

Список теперь начинается с пустого массива. loading показывает загрузку,
loadError хранит её ошибку, reload запускает повтор. hasLoaded отличает
успешно загруженный пустой список от отсутствия ответа сервера.

```jsx
 27 |   useEffect(() => {
 28 |     const controller = new AbortController();
 29 |     loadController.current = controller;
 30 |     setLoading(true);
 31 |     setLoadError('');
 32 |     setError('');
 33 |     setMessage('');
 34 |     async function load() {
 35 |       try {
 36 |         const rows = await fetchPosts(controller.signal);
 37 |         if (controller.signal.aborted) return;
 38 |         if (!Array.isArray(rows)) throw new Error('Сервер вернул неверный формат списка.');
 39 |         setPosts(rows);
 40 |         setHasLoaded(true);
 41 |       } catch (cause) {
 42 |         if (controller.signal.aborted) return;
 43 |         if (cause.status === 401) onUnauthorized();
 44 |         else setLoadError(cause.message);
 45 |       } finally {
 46 |         if (!controller.signal.aborted) setLoading(false);
 47 |       }
 48 |     }
 49 |     load();
 50 |     return () => controller.abort();
 51 |   }, [reload, onUnauthorized]);
```

Создаём AbortController и передаём signal в fetchPosts. После await проверяем,
не отменён ли запрос, затем устанавливаем posts. Старый ответ после отмены
не должен заменять новый список. В finally выключаем loading только для
актуальной загрузки. Cleanup вызывает abort при размонтировании или перед
новой загрузкой. reload меняется кнопкой повтора через setReload(n => n + 1).

useRef хранит текущий контроллер, не создавая рендер при изменении ссылки.
cancelLoad вызывает abort вручную и показывает возможность повторить запрос.
Отмена ожидания не гарантирует отмену уже выполняющегося SQL на сервере.

## 5 Сделали оптимистичное добавление и редактирование

```jsx
 78 |     const snapshot = posts;
 79 |     const temporaryId = `temp-${crypto.randomUUID()}`;
 80 |     setError('');
 81 |     setFormError('');
 82 |     setMessage('');
 83 |     setPending(editingId ? 'Сохраняем изменения…' : 'Добавляем публикацию…');
 84 |     // Интерфейс меняется до получения ответа API.
 85 |     if (editingId) {
 86 |       setPosts(previous => previous.map(post => post.id === editingId ? { ...post, ...values, pending: true } : post));
 87 |     } else {
 88 |       setPosts(previous => [...previous, { ...values, id: temporaryId, createdAt: new Date().toISOString(), pending: true }]);
 89 |     }
 90 |     try {
 91 |       const saved = editingId ? await updatePost(editingId, values) : await addPost(values);
 92 |       const id = editingId || temporaryId;
 93 |       setPosts(previous => previous.map(post => post.id === id ? saved : post));
 94 |       setMessage(editingId ? 'Изменения сохранены на сервере.' : 'Публикация сохранена на сервере.');
 95 |       resetForm();
 96 |     } catch (cause) {
 97 |       // Одновременно разрешена одна операция, поэтому снимок безопасен для отката.
 98 |       setPosts(snapshot);
 99 |       setError(`${cause.message} Изменение отменено. Введённые данные оставлены в форме.`);
100 |       if (cause.status === 401) onUnauthorized();
101 |     } finally {
102 |       setPending('');
103 |     }
```

Перед изменением сохраняем snapshot — прежний массив. Для добавления создаём
временный id с префиксом temp-. Карточка сразу появляется в posts и получает
pending=true. После await addPost настоящий объект из PostgreSQL заменяет временный.
Для редактирования сразу заменяются поля существующей записи, затем отправляется PUT.

Если запрос отклонён, setPosts(snapshot) возвращает прежний список. Форма
сохраняет введённые данные, чтобы их не вводить снова. На время отправки
остальные изменения блокируются, поэтому другой запрос не будет затёрт откатом.
setPending('') в finally снимает блокировку и при успехе, и при ошибке.

## 6 Удаление с возвратом карточки

```jsx
116 |   async function deletePost(id) {
117 |     if (locked) return;
118 |     const snapshot = posts;
119 |     setPosts(previous => previous.filter(post => post.id !== id));
120 |     setPending('Удаляем публикацию…');
121 |     setError('');
122 |     setMessage('');
123 |     try {
124 |       await removePost(id);
125 |       if (editingId === id) resetForm();
126 |       setMessage('Публикация удалена на сервере.');
127 |     } catch (cause) {
128 |       setPosts(snapshot);
129 |       setError(`${cause.message} Удаление отменено, карточка восстановлена.`);
130 |       if (cause.status === 401) onUnauthorized();
131 |     } finally {
132 |       setPending('');
133 |     }
134 |   }
```

Сначала filter убирает карточку, затем отправляется DELETE. При успехе
сервер отвечает 204. При ошибке возвращаем snapshot вместе с карточкой.
Поиск и сортировка из ЛР4 сохранены: они вычисляются по загруженному массиву.

## 7 Форма и карточка

PostForm.jsx сохранил контролируемые поля value/onChange. Добавилось mediaUrl,
потому что ссылка обязательна в нашей Sequelize-модели Post. Вся форма находится
в fieldset disabled во время запроса. Длины по-прежнему ограничены в обработчике
ввода и maxLength. До запроса проверяются пустые/пробельные поля.

PostCard.jsx показывает pending как «Отправляется…». Кнопки действий блокируются
на время запроса. mediaLink разрешает HTTP/HTTPS и локальный путь /media/.
Для локальных материалов ссылка ведёт на API, который отдаёт демонстрационные файлы.
Загрузка новых файлов в этой работе не реализована.

main.jsx и index.html по-прежнему запускают React. В styles.css добавлены экран
входа, индикатор загрузки, сообщения и состояние отправки. Redux не нужен.

## 8 Минимальные изменения сервера

server.js подключает cors для адресов клиента и ограничивает JSON до 32 КБ.
DEMO_DELAY_MS необязательно задерживает реальные запросы для показа загрузки.
По умолчанию задержка выключена, в production игнорируется.

В routes/postRoutes.js перед всеми операциями добавлен router.use(authenticate).
Поэтому доступ к публикациям требует JWT. Используется middleware ЛР3.

В controllers/postController.js сохранён существующий Sequelize CRUD. Добавлены
ограничения строк, идентификаторов, чисел и ссылок. При PUT отсутствующие comments
и likesCount сохраняются, а не очищаются. Ограничения вынесены в config/postLimits.json.
Модели и схему БД для ЛР5 менять не потребовалось. Правка кавычек в models/user.js
была локальным изменением пользователя и не входит в реализацию лабораторной.

## 9 Последовательность одного добавления

Ввод → setForm → submit → временная карточка → fetch POST с Bearer JWT →
Express → authenticate → контроллер → Sequelize → PostgreSQL → ответ201 →
замена временной карточки настоящим объектом.

При отказе запроса вместо последнего шага выполняется откат списка.
Это откат интерфейса. Если сервер успел записать данные до обрыва ответа,
нужно обновить список после восстановления связи. Повторять POST автоматически нельзя.

## Контрольные вопросы кратко

1. Fetch встроен в браузер, axios нужно установить. Fetch требует явной проверки
   response.ok, axios обычно отклоняет Promise при неуспешном HTTP-статусе и имеет interceptors.
2. loading=true перед GET, false в finally. JSX показывает индикатор.
3. Оптимистичное обновление: показать временную карточку → POST → заменить id
   ответом сервера. При отказе вернуть прежний список.
4. При 500 проверить response.ok, создать ошибку и показать её через состояние.
5. AbortController передаёт signal запросу, abort прекращает ожидание.
6. Fetch: method POST, Content-Type application/json, body JSON.stringify(values).
   Axios: axios.post(url, values). В проекте используется первый вариант.
7. Сетевая ошибка попадает в catch. В нашем сервисе показывается «Сервер недоступен».
8. Повтор GET: до трёх попыток, catch → задержка → следующая попытка.
   В проекте выбран ручной повтор кнопкой, автоматического retry нет.
9. В axios interceptor записывает config.headers.Authorization = `Bearer ${token}`
   и возвращает config. У нас такой заголовок устанавливает общий request на fetch.
10. Debounce переносит действие до паузы во вводе: новый символ отменяет прежний
    таймер и запускает новый. Поиск ЛР5 локальный и выполняется сразу.
11. В cleanup эффекта вернуть () => controller.abort(). Так сделано в PostList.
12. Замедлить сеть в DevTools или запустить API с DEMO_DELAY_MS=1800.
    Наш демонстрационный параметр не подменяет БД и ответы.
13. Infinite scroll: загружать страницы limit/offset при появлении нижнего элемента,
    добавлять результаты и прекращать запросы после конца данных. В проекте этого нет.
14. До изменения сохранить snapshot, при ошибке вернуть его и показать сообщение.
15. При FormData не устанавливать Content-Type multipart/form-data вручную:
    браузер сам добавит boundary. Authorization можно оставить.
16. Для фоновой операции отдельный pending: подпись, отметка на карточке и
    отключение повторных действий. Общий список при этом остаётся на экране.

## Как показать и как переключить ветку

Перед переключением остановить клиент и API через Ctrl+C. Из папки CourseProject:

ЛР4: git switch 24, затем npm --prefix client run dev. API не нужен.
ЛР5: git switch 25, npm start. Во втором терминале npm --prefix client run dev.
После смены ветки обновить браузер. Если зависимости ещё не установлены,
выполнить npm ci в корне и npm --prefix client ci для клиента.

Для ЛР5 открыть localhost:5173, войти, добавить свою запись, изменить её,
обновить страницу, показать сохранённую правку. Затем удалить свою запись.
При задержке 1800 мс показать временную карточку и отмену загрузки.
Остановить только API, показать сообщение ошибки и откат, запустить API снова,
нажать повтор загрузки. Supabase останавливать не нужно.

Проверки: npm run test:api — 30 проверок с настоящей БД. npm --prefix client test —
23 клиентских теста с подменой HTTP. npm --prefix client run build — сборка.
