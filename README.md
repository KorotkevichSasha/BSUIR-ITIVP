## Запуск

Требуется Node.js 22.12+ (проверено на 22.14.0).

```powershell
cd client
npm ci
npm run dev
```

Открыть адрес, напечатанный Vite, обычно http://localhost:5173/.
Для работы с той же коллекцией использовать тот же браузер и адрес:
`localhost` и `127.0.0.1`, а также разные порты имеют разные хранилища.

```powershell
npm test
npm run build
npm run preview
```

`preview` открывает производственную сборку, обычно на порту 4173.
На этом адресе будет отдельная коллекция.

## Возможности и проверка

1. При первом открытии показаны два примера игровых публикаций.
2. Заполнить заголовок, игру, тип и описание. Нажать «Добавить публикацию»
   или Enter в однострочном поле. Enter в описании переносит строку.
3. Нажать «Изменить», изменить текст, сохранить. Идентификатор и время
   создания сохраняются. «Отмена» возвращает форму к добавлению.
4. Проверить поиск по заголовку, игре или описанию, фильтр типа и три
   порядка сортировки. Они меняют отображение, а не исходный массив.
5. После надписи «Сохранено в браузере» перезагрузить страницу.
   Список и правки останутся. Поиск, порядок и незавершённая форма сбросятся.
6. Удалить запись, перезагрузить. Она не должна восстановиться.
   После удаления всех записей сохраняется пустой массив, примеры не возвращаются.
7. В инструментах разработчика открыть Application → Local Storage →
   http://localhost:5173 → `game-media-posts-v1`. Значение — JSON-массив.
   Это удобно показать преподавателю вместе с восстановлением после F5.

## Где находится код

- `client/index.html` и `src/main.jsx`: подключение React и запуск дерева компонентов.
- `src/App.jsx`: общий каркас, закреплённая шапка и подвал.
- `src/components/PostList.jsx`: состояния, CRUD, поиск, сортировка и заголовок вкладки.
- `src/components/PostForm.jsx`: контролируемые поля и общая форма добавления/редактирования.
- `src/components/PostCard.jsx`: отображение записи и кнопки действий.
- `src/hooks/useLocalStorage.js`: начальное чтение, сохранение с задержкой 500 мс,
  очистка таймера и обработчика `pagehide`, обработка ошибок хранилища.
- `src/data.js`: примеры, ключ хранилища, ограничения и проверка структуры JSON.
- `src/styles.css`: оформление и адаптация под узкий экран.
- `src/hooks/useLocalStorage.test.jsx`: 11 проверок сохранения, восстановления,
  пустого списка, отмены таймера, размонтирования и ошибок чтения/записи.

## Ограничения

Сохраняются данные публикаций, без загрузки файлов и обращения к REST API.
Поля ограничены: заголовок — 100, игра — 80, описание — 1000, поиск — 100
символов. Максимум 500 публикаций. Пустые и пробельные поля не принимаются.
Пользовательский текст React выводит как текст, без вставки HTML.

Массив читается при монтировании в эффекте с `[]`. Флаг `loaded` не позволяет
первому пустому состоянию затереть существующие данные. Эффект с зависимостями
`[posts, loaded, canSave]` записывает JSON через 500 мс после последней правки.
Cleanup отменяет прежний таймер. Событие `pagehide` сохраняет актуальный список
при обычном уходе со страницы. Аварийное завершение браузера до автосохранения
может потерять последнюю правку. Перед демонстрацией перезагрузки дождаться статуса сохранения.

Если JSON повреждён или запрещено чтение, приложение показывает примеры и
предупреждение. Изменения работают в памяти, исходные данные не перезаписываются.
Для восстановления можно сохранить копию значения в DevTools, исправить или
удалить только ключ `game-media-posts-v1` и перезагрузить страницу.
При переполнении хранилища текущие данные остаются в памяти, отображается ошибка.
Удаление данных сайта в браузере удалит коллекцию. Синхронизация вкладок в ЛР4
не реализована. В ЛР5 хранилище будет заменено обращениями к серверу.
