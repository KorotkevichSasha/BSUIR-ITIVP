# Game Media — ПЗ1 «Middleware и шаблонизаторы»

Ветка `pz21`, вариант 13. Express + EJS, тематика — обмен игровыми скриншотами и видео.

## Запуск

Требуется Node.js 18+ и доступ к PostgreSQL (используется существующий Supabase).

```bash
npm install
npm run db:migrate
npm start
```

В локальном `.env` должны быть `DATABASE_URL`, `JWT_SECRET` из ЛР3 и при необходимости `PORT` (по умолчанию 3001). `.env` не коммитится.

## Страницы и проверка

Адрес по умолчанию: `http://localhost:3001`.

| Запрос | Ожидаемый результат |
| --- | --- |
| `GET /` | 200, список публикаций из массива |
| `GET /item/1` | 200, детальная страница |
| `GET /item/999999` | 404, отдельный EJS-шаблон |
| `GET /add` | 302, переход на `/login` |
| `GET /add?auth=1` | 200, форма, пользователь Александр |
| `POST /add` без `auth=1` | 302 на `/login`, публикация не создаётся |
| `POST /add?auth=1` | При корректных полях — 302 на `/`, запись появляется в списке |
| `POST /add?auth=1` с пустыми полями или неверной ссылкой | 400, форма с сообщением об ошибке |
| `GET /unknown` | 404, отдельный EJS-шаблон |
| `GET /test-error?auth=1` | 500, отдельный EJS-шаблон; ошибка в консоли |
| `GET /logs?auth=1` | 200, последние 100 записей журнала из PostgreSQL |

Проще проверить добавление через форму браузера. Она отправляет `application/x-www-form-urlencoded`; поля: `title`, `game`, `mediaType` (`screenshot` / `video`), `mediaUrl` (http/https), `description`.

## Хранение и middleware

- `data/items.js`: публикации ПЗ находятся в массиве, после перезапуска возвращаются начальные записи. Начальные URL на example.com — демонстрационные ссылки; через форму можно добавить ссылку на своё медиа.
- `middleware/pageAuth.js`: **учебная имитация**, строго проверяет `?auth=1`. Это не настоящая защита. JWT-маршруты ЛР3 `/auth`, `/profile`, `/admin` работают отдельно.
- `middleware/requestLogger.js`: регистрируется до статики и маршрутов. На событии `finish` выводит время, метод, URL, статус и длительность в консоль и сохраняет запись в таблицу `RequestLogs` (требование для нечётного варианта). Тела запросов, пароли и заголовки авторизации не записываются. При ошибке БД пишет сообщение в консоль, приложение продолжает работу.
- `middleware/errors.js`: после маршрутов находятся 404 и обработчик с четырьмя аргументами для 500. Страницы получают HTML, API ЛР2/ЛР3 — JSON.
- `views/partials`: общий HTML-каркас; пользовательские данные выводятся через `<%=` с экранированием.

Порядок: журнал → статика → разбор JSON/форм → маршруты → 404 → обработчик ошибок.

Запись в БД выполняется после ответа: обновите `/logs?auth=1`, чтобы увидеть недавний запрос. Журнал сохраняется между перезапусками. В Supabase Table Editor можно открыть `public.RequestLogs` или выполнить:

```sql
SELECT * FROM public."RequestLogs" ORDER BY id DESC LIMIT 20;
```

Существующие API-маршруты `/posts`, `/auth/register`, `/auth/login`, `/profile`, `/admin` сохранены. Главная `/` теперь показывает страницу EJS.
