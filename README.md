# Game Media — ПЗ1 «Middleware и шаблонизаторы»

Ветка `pz21`, вариант 13: журнал запросов хранится в **файле** `logs/requests.log`.
Публикации ПЗ находятся в массиве `data/items.js`, после перезапуска возвращаются начальные записи.

## Запуск

```bash
npm install
npm start
```

По умолчанию: http://localhost:3001. Для API предыдущих лабораторных используется существующий `.env` с `DATABASE_URL`, `JWT_SECRET` и при необходимости `PORT`. Секреты не коммитятся. Миграция таблицы журнала из ранней версии сохранена в истории, но текущее логирование её не использует.

## Проверка

- `/` — список публикаций; `/item/1` — детали, лайки и время создания.
- `/add` — переход на `/login`; `/add?auth=1` — форма. Это учебная имитация входа.
- `POST /add?auth=1` — принимает `title`, `game`, `mediaType`, `mediaUrl`, `description`, `likesCount` (формат формы или JSON).
- Проверки строк после `trim()`: название 1–100, игра 1–80, URL 1–2048, описание 1–1000 символов. Пробельные строки не принимаются. URL — только http/https, тип — screenshot/video. Лайки — целое число от 0 до 1000000. Правила вынесены в `config/validation.json` и используются сервером и формой.
- При ошибках: HTTP 400, все сообщения над формой, введённые значения сохранены. При успехе: 302 на главную. Сервер назначает ID и уникальное время создания, клиент не может их задать.
- `/missing` и `/item/999999` — страница 404.
- Ссылка «Демонстрация 500» в закреплённой шапке ведёт на `/test-error?auth=1`. Ответ — EJS-страница 500 с пояснением и навигацией.
- `/logs?auth=1` — последние 100 записей, прочитанных из файла журнала.

## Логирование и обработка ошибок

Каталог и файл создаются автоматически. Формат — JSON Lines: время запроса, метод, URL. Запись выполняется **до** маршрута. Если файл нельзя открыть или записать, `next(error)` передаёт управление обработчику 500; исходное действие не выполняется. Статика подключена раньше логирования: CSS страницы ошибки остаётся доступным даже при сбое файла. Подробная причина ошибки выводится в консоль; пароли, тела запросов и Bearer-заголовки не записываются.

Для проверки сбоя на отдельном экземпляре сервера задайте `REQUEST_LOG_FILE` путём к каталогу вместо файла. Запрос вернёт 500, сервер продолжит работу. Логи исключены из Git.

Порядок middleware: статика → логирование в файл → разбор JSON/форм → маршруты → 404 → обработчик ошибок с четырьмя параметрами.

API `/posts`, `/auth`, `/profile`, `/admin` предыдущих лабораторных сохранено и использует JWT независимо от учебного входа ПЗ.
