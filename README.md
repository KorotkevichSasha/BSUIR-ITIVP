# Game Media — ПЗ1 «Middleware и шаблонизаторы»

Ветка `pz21`, вариант 13. По требованиям нашей группы журнал хранится в таблице **RequestLogs** PostgreSQL/Supabase.
Публикации страниц ПЗ хранятся в массиве `data/items.js` до перезапуска сервера.

## Запуск

```bash
npm install
npm run db:migrate
npm start
```

Сайт: http://localhost:3001. Используется существующий `.env` с `DATABASE_URL`, `JWT_SECRET` и необязательным `PORT`. Секреты исключены из Git. Таблица журнала создаётся существующей миграцией `20261016120000-create-request-log.js`.

## Проверка страниц

- `/` — список. `/item/1` — детали. «Открыть медиа» открывает локальную иллюстрацию или воспроизводимый MP4 из `public/media`. Это демонстрационные материалы, а не настоящие кадры из игр.
- `/add` перенаправляет на `/login`. `/add?auth=1` открывает форму. Учебный параметр не заменяет JWT в API предыдущих лабораторных.
- `POST /add?auth=1` принимает строковые поля `title`, `game`, `mediaType`, `mediaUrl`, `description`, `likesCount`.
- Пустые и пробельные поля отклоняются. Пределы: название 100, игра 80, адрес 2048, описание 1000, тип медиа 20 символов, лайки 7 цифр. Лайки — целое неотрицательное число. Длина проверяется до преобразования в Number. Формат адреса и перечень типов на сервере не проверяются. Небезопасный протокол выводится простым текстом, без активной ссылки.
- Ошибка ввода: 400 и форма с сообщениями. Успех: 302 на главную. ID и уникальное время создания задаёт сервер.
- `/missing`, `/item/999999`, удалённый `/test-error?auth=1` — 404 при доступной БД.
- `/logs?auth=1` — до 100 последних записей из RequestLogs с методом, адресом, кодом ответа и длительностью.

## Логирование в БД и ошибка 500

Middleware сначала ожидает `RequestLog.create()`, затем вызывает `next()`. Начальные `statusCode: 0` и `durationMs: 0` обозначают незавершённый запрос. После события `finish` код и длительность обновляются. Текущая запись страницы журнала может отображаться как «В обработке», поскольку её ответ ещё формируется.

Если первичная запись в PostgreSQL не удалась, middleware вызывает `next(error)`. Обычный маршрут не выполняется. Пользователь получает EJS-страницу 500 с пояснением. CSS и локальные медиа подключены до логирования и доступны при сбое. При ошибке обновления результата после `finish` причина выводится в консоль, поскольку ответ уже отправлен.

На сайте нет кнопки или специального маршрута для вызова 500. Для воспроизводимой проверки реального обрыва соединения:

```bash
npm run demo:db
```

Откройте http://localhost:3002, в терминале введите `off` и обновите страницу. Локальный TCP-посредник закроет соединения с настоящей БД. Приложение останется работать и вернёт 500 при попытке записи журнала. Введите `on`, обновите страницу — снова получите 200. `exit` завершает тестовый экземпляр. Основной сервер на 3001 и сам Supabase продолжают работать. Порт 15432 используется только для локального соединения тестового экземпляра.

Это проверка настоящей ошибки соединения PostgreSQL, а не заранее выброшенное исключение. Если остановить саму БД, основной сервер обработает отказ тем же middleware. Ошибка первичного подключения при запуске выводится в терминал, сервер в таком случае ещё не слушает порт.

## Ограничение ресурсов

Все пределы находятся в `config/validation.json`.

- Тело JSON/формы до 32 КиБ, до 12 параметров формы. Превышение — 413.
- До 120 динамических запросов в минуту с одного IP. Превышение — 429 с `Retry-After`, до обращения к БД.
- В массиве до 1000 публикаций. Длинные неразрывные строки переносятся внутри карточек.
- Просмотр журнала выполняет запрос с `limit: 100`, вся таблица в память не загружается. Записи хранятся в PostgreSQL, файловый журнал больше не используется. Резервирование и срок хранения таблицы определяются настройками БД.
- Таймаут установки соединения с БД — 5 секунд, ожидания соединения из пула — 7 секунд.

Ограничитель действует в одном процессе и сбрасывается при его перезапуске. Публичный сайт требует защиты хостинга от распределённой сетевой атаки.

Порядок middleware: статика → ограничение частоты → запись в БД → ограниченный разбор тела → маршруты → 404 → обработчик ошибок с четырьмя параметрами.

API `/posts`, `/auth`, `/profile`, `/admin` сохранено. Миграция `20261016220000-use-local-demo-media.js` заменяет только два прежних адреса медиа на example.com в начальных записях Posts. Переустановка сидов или удаление пользовательских записей для этого не нужны.
