# ЛР5 — взаимодействие React с сервером

Ветка `25`, Короткевич А. Г., группа 320602, вариант 13.

Клиент из ЛР4 теперь получает и изменяет публикации через собственный Express API.
Коллекция хранится в PostgreSQL (Supabase). В `localStorage` сохраняется только
JWT под ключом `game-media-jwt`. Коллекция ЛР4 `game-media-posts-v1` не изменяется.
Все вошедшие пользователи работают с общей коллекцией, разграничение по владельцам
в этой лабораторной не вводилось.

## Запуск ЛР5

Нужен Node.js 22.12+ и существующий локальный `.env` в корне:
`DATABASE_URL` и `JWT_SECRET`. Значения из `.env` не публикуются.
Модели и миграции взяты из ЛР3. Для уже настроенной базы новая миграция не нужна.

Первый терминал, папка `CourseProject`:

```powershell
git switch 25
npm ci
npm start
```

Второй терминал, та же папка:

```powershell
npm --prefix client ci
npm --prefix client run dev
```

Сайт: http://localhost:5173/.
Сервер: http://localhost:3001/. JSON по корневому адресу API является нормальным.
Войти существующим аккаунтом ЛР3 или зарегистрироваться через форму на сайте.
При регистрации автоматически выполняется вход. JWT действует один час.
После HTTP 401 клиент предлагает войти повторно.
Если проект Supabase приостановлен, сначала возобновить его в панели Supabase.

Последовательный разбор изменённого кода и ответы на контрольные вопросы:
[ЛР5-разбор.md](./ЛР5-разбор.md).

Клиент использует `VITE_API_URL=http://localhost:3001`. Это значение задано
по умолчанию, пример находится в `client/.env.example`. При необходимости
создать `client/.env` с другим адресом и перезапустить Vite.
`JWT_SECRET` и `DATABASE_URL` в клиент не переносить.

## Как переключаться между работами

Перед переключением остановить оба процесса через Ctrl+C в их терминалах.
Файлы приложения меняются веткой Git, запущенный Node.js требует перезапуска.

Для ЛР4:

```powershell
git switch 24
npm --prefix client ci
npm --prefix client run dev
```

Работа открывается на http://localhost:5173/ и использует хранилище браузера.
API для ЛР4 запускать не нужно.

Для ЛР5 выполнить команды запуска ветки `25`, приведённые выше.
После перехода обновить вкладку браузера. Для ЛР3 используется ветка `23`.
Локальные `.env` остаются на диске при переключении и не входят в Git.

## Что реализовано

- Регистрация, вход и выход через существующие `/auth/register` и `/auth/login`.
- Автоматическая подстановка `Authorization: Bearer ...` в запросы коллекции.
- GET `/posts` с индикатором загрузки, обработкой ошибок и кнопкой повтора.
- POST `/posts`: временная карточка сразу, замена настоящей записью после ответа.
- PUT `/posts/:id`: немедленная правка, откат при ошибке.
- DELETE `/posts/:id`: немедленное удаление, восстановление при ошибке.
- Одна операция изменения одновременно, чтобы откат не затирал другую операцию.
- Дополнительное улучшение: AbortController отменяет загрузку при размонтировании,
  повторной загрузке и по кнопке «Отменить загрузку». Опоздавший ответ игнорируется.
- Поиск, фильтр типа и сортировка из ЛР4 выполняются на клиенте по загруженному списку.
- Ссылка на материал, которую требует существующая модель Post.
- CORS для localhost/127.0.0.1 на портах 5173 и 4173.
- Ограничение тела JSON до 32 КБ и длины полей в `config/postLimits.json`.

## Сценарий показа преподавателю

1. Открыть сайт, войти или зарегистрироваться. Показать индикатор и загруженные записи.
2. Заполнить заголовок, игру, тип, ссылку и описание.
   Пример ссылки: `/media/winning-goal.mp4` или `/media/night-city.svg`.
3. Добавить запись. Сначала видна отметка «Отправляется…», затем подтверждение сервера.
4. Изменить свою тестовую запись. Обновить страницу: правка должна остаться.
5. Проверить поиск, тип и сортировку.
6. Нажать «Обновить список», затем «Отменить загрузку», затем повторить запрос.
7. Остановить только локальный API через Ctrl+C, оставив Vite запущенным.
   Нажать «Обновить список»: появится сообщение о недоступности сервера и кнопка повтора.
8. При наличии ранее загруженных карточек попробовать изменить/удалить свою тестовую
   запись: операция откатится, появится объяснение ошибки.
9. Запустить API снова и нажать «Повторить загрузку».
10. Удалить тестовую запись при работающем API и обновить страницу.
    Исходные записи других пользователей при проверке не удалять.

Для заметного показа загрузки и промежуточной карточки можно перед запуском API:

```powershell
$env:DEMO_DELAY_MS='1800'
npm start
```

Задержка относится к настоящим запросам, обработчики продолжают работать с PostgreSQL.
Выключить её перед обычным запуском:

```powershell
Remove-Item Env:DEMO_DELAY_MS -ErrorAction SilentlyContinue
npm start
```

Это параметр разработки с пределом 5 секунд. В production он игнорируется.
Supabase для демонстрации недоступности останавливать не требуется.

## Проверки

```powershell
npm run test:api
npm --prefix client test
npm --prefix client run build
```

`test:api` запускает Express на свободном порту и делает 30 проверок с настоящей
PostgreSQL. Создаёт отдельного временного пользователя и публикацию, удаляет только
свои записи в finally. Требуется доступная настроенная БД.

Клиентские 23 теста проверяют API-обёртку, оптимистичные изменения и откаты,
состояния загрузки, отмену и StrictMode. В них HTTP-ответы подменены специально
для воспроизводимого отказа и задержки. Браузерная проверка выполняется отдельно
с настоящим сервером и базой.

## Файлы

- `client/src/api.js`: Fetch API, URL сервера, JWT, обработка HTTP/сетевых ошибок.
- `client/src/App.jsx`: выбор формы входа или коллекции, выход из сеанса.
- `client/src/components/AuthForm.jsx`: регистрация и вход.
- `client/src/components/PostList.jsx`: загрузка, отмена и оптимистичный CRUD.
- `client/src/components/PostForm.jsx`: контролируемая форма с ссылкой на материал.
- `client/src/components/PostCard.jsx`: данные записи, ссылка и состояние отправки.
- `server.js`: CORS, JSON, маршруты и обработка ошибок.
- `routes/postRoutes.js`: проверка JWT перед маршрутами публикаций.
- `controllers/postController.js`: существующий CRUD и ограничения размера ввода.
- `config/postLimits.json`: ограничения строк на сервере.

Клиентский откат означает возврат прежнего отображения. Если соединение оборвалось
после записи в БД, сервер мог успеть выполнить операцию. В этом случае обновить
список после восстановления связи. Автоматического повтора POST/PUT/DELETE нет.
Отмена GET прекращает ожидание на клиенте и не гарантирует остановку уже начатого
SQL-запроса. Данные вкладок согласуются повторным GET, push-синхронизации нет.
